# Forecaster — MVP планирования поддержки

Локальное веб-приложение строит почасовой прогноз по исторической нагрузке, накладывает действующий график и показывает дефицит мощности и ориентир по найму.

## Запуск

```bash
cd /Users/azoniks/Projects/forecaster
python3 app.py
```

Открыть: http://127.0.0.1:8088

Внешние библиотеки не требуются. При первом запуске большой файл `нагрузка` агрегируется в `cache/history.json`; следующие запуски используют кэш.

## Правила модели

- один ряд исходной нагрузки считается одним периодом;
- технические, архивные и исключённые из прогноза очереди не учитываются;
- `Метрика: metrika_chats` обслуживается младшими и специалистами;
- остальные очереди подлинии 1 — специалистами;
- подлиния 2 — экспертами;
- ночные эксперты сначала закрывают экспертные очереди, затем очереди подлинии 1;
- мощность младшего/специалиста — 4 периода в час, эксперта — 3,2;
- профиль строится по дню недели и часу в часовом поясе Москвы;
- краткосрочные скачки не продолжаются автоматически: используется стабильный профиль дня недели и часа, а известные будущие изменения задаются в сценарии вручную;
- неполные последние дни выгрузки исключаются автоматически;
- качество проверяется на нескольких независимых исторических окнах отдельно по дневному WAPE, распределению нагрузки по часам, строгому WAPE «час × группа» и смещению;
- рекомендация по найму — расчётный ориентир, а не оптимизатор смен. Она переводит непокрытые периоды в 40-часовые ставки и выбирает наиболее подходящий типовой график.

Сценарий позволяет выбрать лист графика, горизонт, глубину истории, резерв мощности и вручную скорректировать рост каждой группы очередей.

## Должности и компетенции

На вкладке «Настройки» можно включать и отключать должности, менять их производительность, связывать с названием должности в файле графика и задавать доступные группы очередей отдельно для дневных и ночных смен. Конфигурация сохраняется локально в `config/staffing.json`.

## Создание графика на новый месяц

На вкладке «Графики работы» кнопка «Добавить следующий месяц» переносит состав команды из выбранного месяца и автоматически расставляет смены. График 2/2 продолжается без сброса цикла на границе месяца. Для графика 5/2 рабочими считаются будни, кроме российских нерабочих праздничных и утверждённых переносных выходных дней; сотрудники 2/2 в праздники продолжают работать по своему циклу.

## Отпускная ёмкость

Для каждого месяца и должности приложение оценивает сезонность по средней дневной исторической нагрузке. Пиком считается месяц с нагрузкой не менее 115% от среднегодовой: в пик лимит одновременных отсутствий равен 10% команды, в остальные месяцы — 20%, с округлением вниз. В лимит входят отпуска, больничные и обучения. Итоговое количество дополнительно проверяется по фактическому графику и почасовому прогнозу. Если покрытие критично, приложение предлагает субботник с датой, должностью, количеством сотрудников и рекомендуемым временем смены.

## Обновление исторических данных

В блоке «Исторические данные» можно загрузить новую TSV-выгрузку. Обязательные колонки: `Очередь`, `Начало периода`, `Канал`. В нагрузку входят созданные, переведённые и переоткрытые периоды, поскольку каждый из них требует работы в соответствующей очереди. После проверки файл заменяет текущую историю, агрегаты пересобираются, а предыдущая версия сохраняется в папке `backups/`.

Там же можно загрузить новый справочник `очереди.xlsx`. В XLSX требуется лист `Chart data` и колонки `Очередь`, `Подлиния`, `Техническая очередь`, `Архивная очередь`, `Учитываем в прогнозе`. После обновления справочника история пересобирается с новыми правилами, а предыдущий файл сохраняется в `backups/`.
